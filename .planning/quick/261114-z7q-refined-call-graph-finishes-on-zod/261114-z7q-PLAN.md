**Growth law.** For a function whose body follows `k` calls back into itself (or into a cycle through it), one
entry at invocation depth `d0` performs `I(d0) = sum_{j=0}^{17-d0} k^j ~ k^(18-d0) / (k-1)` invocations, i.e.
`Theta(k^D)` in the remaining depth `D = 18 - d0`, independent of how many distinct inputs the walk sees (here one).
The measured walk entered at depth 6: `(4^12 - 1) / 3 = 5.59M` invocations, about 11 s, per entry, and the return
pass makes one such entry per function whose body reaches `deepPartialify`. The function's own summary enters at
depth 1: `(4^17 - 1) / 3 = 5.7 x 10^9` invocations, about 3.1 h at the measured rate, and `deepPartial`'s summary
(depth 2) another `1.4 x 10^9`. The main pass repeats the same entries. The constant per invocation (string and env
churn in the pprof) is not the cause; the count is.

**Why the existing bounds do not help.** The depth cap bounds depth, not breadth, so the work it admits is
exponential in the cap. A lower cap would trade recall for time and still grow as `k^cap`.

**Not a design limit.** The walk recomputes the same answer: within one pass of one file, the invocation of a
function with the same callee env, depth and walk context is a pure function of that input and of the collector's
tables, and the four sibling calls at each level have identical input. A contained, exact fix exists.

2. **Exact invocation memo.** In `collect_function_flow_invocation`, after the depth check, look up the outcome of
   a previous walk with the same input; on a miss walk, then record the outcome.
   - Key: callee function, the callee env as handed in, invocation depth, `this_method_walk`, `current_super`, and
     the walk-guard state the walk can observe (frame depth, and when a frame is in flight the remaining budget and
     the in-flight frames). At frame depth 0 every guarded walk starts by refreshing the budget, so the leftover
     budget is not observable there.
   - Outcome: the returned targets, the callee env after the walk, the guard budget after the walk.
   - Validity: a collector `table_generation` counter that every walk-time write to a table a walk reads
     (`classes`, `export_aliases`, `exports`) bumps. An outcome is recorded only when the walk itself bumped
     nothing, and reused only while the generation is unchanged.
   - Exactness: rows are only appended and are sorted and deduplicated at the end, so a skipped re-walk loses no
     row; the tables are unchanged since the recorded walk, so the re-walk would reproduce the same rows, env,
     returned targets and guard spend. Wrong-complete stays 0 and recall cannot move.
   - Expected cost: one walk plus `k - 1` lookups per level, `O(k * D)` per entry instead of `k^D`.
