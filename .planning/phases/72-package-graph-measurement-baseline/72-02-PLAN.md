<objective>
Remove the wrong exact targets the measurement baseline found, before any later stage builds on them.

Purpose: the held-out baseline of 72-01 showed 3 wrong exact targets on the refined plan and 3 answers with other targets and no unresolved marker on each plan, all in acorn (`Parser.parse`, `Parser.parseExpressionAt`, `Parser.tokenizer`). They share one construct: `Ctor.m(...)` inside a function named `m`, where `Ctor.m` is a function expression assigned to a constructor function. polint names that function expression anonymously, so the only function named `m` is the caller; the lexical fallback in `calls/direct.rs` resolves the member call to the caller by name with `Heuristic` precision. The call layer counted that answer as complete, and the summary-assisted refined edge re-stated it as `SetupAware`, an exact claim. A wrong exact claim is a stop-and-fix (`research/package-graphs/TARGETS.md`), so it is fixed inside the phase that measured it.
Output: the construct with a tune case and a held-out case; three engine fixes, each pinned by a kernel test that fails without it.
</objective>

  <name>Task 5: a typed target is exact only where the checker's answer is the call's</name>
  <action>
    Added to this plan when the typed plan (the refined plan with `type_sidecar = true`) was measured: it had wrong exact targets on every set, 213 on the held-out set. The held-out cases were read only after the general fix, to confirm it; none was tuned on. The causes, from the tune set and the constructs: (a) without a resolved signature the sidecar took the receiver's symbol, so `this.emit(...)` named the class; (b) a property assigned in two places (`target.parseArg`) answered with one of them; (c) a resolved signature whose declaration is not the binding's value (a factory's result, a reassigned `let`, underscore's `isFunction$1`) was written `declared`; (d) a sidecar call joined the native call around it by containment or a shared start; (e) a declaration no native function is named for joined its enclosing function. Fixes: in the sidecar, the fallback reads the callee's own symbol; a `new` or `super(...)` names the class its callee names; a resolved target is `declared` only when the callee binding holds it alone, otherwise the new `inferred` dispatch, and the first pass records writes (assignments, destructuring, loop variables, updates, overriding subclass members). In Rust, `inferred` and a declared target at a union site are conservative, and the site and callee joins keep only the exact span and the same-end join. The bench stops on a typed candidate that claims exact rather than rereading it. Tests: `a_binding_that_can_hold_another_value_is_never_an_exact_answer`, `a_call_the_checker_answers_keeps_its_exact_target`, and the join and precision unit tests in `refined_calls/ts_types.rs`.
