## Cross-cutting conclusions

1. **Order of attack.** Kernel identity and outcome bugs first (they gate everything persisted or published), then the Go edit tier (the single measured gap against the product promise), then the agent-facing graph CLI (immediate value over the warm cache), then TS parity, then the thin SDK.
2. **Files before SQLite.** Every persistence win in this milestone is reachable with the existing layer-cache conventions (temp-then-rename, manifest + payload, `InvalidationPlan`). Re-open the SQLite decision only with a measured need for cross-run queries.
3. **Byte identity is the universal gate.** Each PR must keep reports identical at 1/4/6 jobs and across permutations, and restored answers must carry the same unknowns and budget state as recomputed ones. Existing gates: `scripts/deep-gate/gate.sh`, `tests/golden-corpus`, `tests/taint-corpus`, the Jelly and Go x/tools lanes, `public_surface_leak`, `internal_architecture`.
4. **The edit cell does not exist in the harness.** Every edit-tier number so far was measured by hand. The first engine PR adds it so later gates are reproducible.
